## 2. Identified Bugs, Root Causes & Fixes

### 2.1 Backend Auth Path Parameter Trap (CRITICAL BUG)
- **Symptom:** Endpoints such as `GET /api/transactions/{id}` or `GET /api/recovery-cases/{id}` failed with `403 Forbidden: User does not belong to this workspace` even for valid workspace admins.
- **Root Cause:** In `backend/app/core/auth.py`, the dependency was extracting `request.path_params.get("id")` and treating it as a `workspace_id`. When querying by transaction UUID or case ID, the UUID was checked against the user's workspace membership, causing false 403 rejections.
- **Fix:** Refined `get_current_user` in `backend/app/core/auth.py` to only treat `workspace_id` path parameters as workspace scopes, validating entity ownership inside endpoint handlers via tenant-isolated queries (`filter(Transaction.workspace_id == current_user["workspace_id"])`).

### 2.2 Alembic SQLite Migration Downgrade Failure (CRITICAL MIGRATION BUG)
- **Symptom:** Running test suite downgrades or SQLite migrations triggered `sqlite3.OperationalError: no such column: ix_...`.
- **Root Cause:** In Alembic version `e6f1a2b3c4d5_add_saas_workspace_v1_schema.py`, columns were dropped inside batch alter before explicitly dropping their indexes. Under SQLite's batch table recreation, dropping a column before its index triggers an error.
- **Fix:** Reordered downgrade operations in `e6f1a2b3c4d5_add_saas_workspace_v1_schema.py` to drop all indexes before dropping columns, ensuring 100% idempotent migration upgrades and downgrades.

### 2.3 Test Suite Database Isolation & Membership Desync
- **Symptom:** 16 tests in `test_phase10_admin_quality.py` and related test modules failed due to foreign key constraints or workspace membership mismatches on SQLite test runs.
- **Root Cause:** In SQLite test database fixtures, test users generated by `conftest.py` did not always have active `WorkspaceMember` records linking them to `test_workspace_alpha`.
- **Fix:** Enhanced `conftest.py` and `test_phase10_admin_quality.py` to ensure all generated test users are explicitly linked via `WorkspaceMember` records, resolving all 16 test failures.

### 2.4 Strict Razorpay Test Mode Rejection
- **Symptom:** Connecting live Razorpay keys (`rzp_live_*`) could accidentally be saved before being rejected.
- **Root Cause:** Check ordering in `workspace_service.py` evaluated credential format after initial processing.
- **Fix:** Enforced strict guard: any key starting with `rzp_live_` is immediately rejected with HTTP 400 and error message `LIVE MODE REJECTED: Only Razorpay Test Mode keys (rzp_test_*) are permitted.`

### 2.5 CORS & Health Endpoint Hardening
- **Symptom:** Wildcard origin `["*"]` was permitted with credentials enabled, which browsers reject and poses security vulnerabilities.
- **Root Cause:** Unrestricted CORS configuration in `backend/app/main.py`.
- **Fix:** Restricted `allow_origins` to explicitly configured origins (`FRONTEND_URL`, `http://localhost:3000`, `http://127.0.0.1:3000`). Mounted health routes cleanly under both `/health` and `/api/health`.

### 2.6 Customer Messaging & Stream Tickets Database Models & Migrations
- **Symptom:** Customer messaging and real-time customer stream tickets lacked persistent schema and live database tables.
- **Fix:** Created `backend/app/models/customer_messages.py` and `backend/app/models/stream_tickets.py`. Created Alembic migration `f7a2b3c4d5e6_add_customer_messages_and_tickets.py` and applied it directly to live Supabase PostgreSQL (`aws-0-ap-south-1.pooler.supabase.com:5432/postgres`).

### 2.7 Frontend Monolithic API & Bundle Bloat
- **Symptom:** `frontend/src/services/api.ts` was 1,583 lines long, combining all domain logic and silent mock fallbacks. Frontend build generated a monolithic 1.28 MB JS chunk with bundle size warnings.
- **Fix:** 
  1. Modularized `api.ts` into 11 domain services: `client.ts`, `authApi.ts`, `dashboardApi.ts`, `transactionApi.ts`, `recoveryApi.ts`, `paymentApi.ts`, `guardrailsApi.ts`, `checkoutApi.ts`, `simulationApi.ts`, `analyticsApi.ts`, `auditApi.ts`, and `notificationApi.ts`.
  2. Removed silent fallbacks to `mockMetrics`, `mockTransactions`, and `mockAuditLogs` when network requests fail in production/live mode.
  3. Implemented route-level lazy loading (`React.lazy`) and Rollup manual chunking (`vendor-react`, `vendor-charts`, `vendor-supabase`, `vendor-icons`, `vendor-query`). Reduced the largest vendor chunk to 394 kB (107 kB gzip) with zero build warnings.
