# Machine Learning Core

RecoverAI utilizes gradient-boosted decision tree models trained with **XGBoost** and **scikit-learn** to predict transaction recovery propensity and optimize intervention strategies via Expected Recovery Value (ERV).

---

## 1. Model Architecture
- **Model 1: Overall Recovery Propensity Model**
  - **Algorithm**: `xgb.XGBClassifier` (Gradient Boosted Trees)
  - **Artifact**: `backend/ml/artifacts/recovery_model.joblib`
  - **Preprocessor**: `backend/ml/artifacts/recovery_preprocessor.joblib` (OneHotEncoder + StandardScaler)
  - **Target**: $P(\text{recovery} \mid X)$
- **Model 2: Action-Conditioned Intervention Success Model**
  - **Algorithm**: `xgb.XGBClassifier` (Gradient Boosted Trees)
  - **Artifact**: `backend/ml/artifacts/intervention_model.joblib`
  - **Preprocessor**: `backend/ml/artifacts/intervention_preprocessor.joblib`
  - **Target**: $P(\text{recovery} \mid X, \text{Action}=a)$ for 7 candidate actions:
    - `RETRY_NOW`
    - `RETRY_LATER`
    - `UPI_SWITCH`
    - `PAYMENT_LINK`
    - `PERSONALIZED_REMINDER`
    - `HUMAN_ESCALATION`
    - `NO_ACTION`

---

## 2. Dataset & Quality Disclosure
> [!IMPORTANT]
> **Dataset Disclosure**: The models are trained and evaluated strictly on **synthetic Indian digital payment telemetry** (35,000 samples generated by `scripts/generate_synthetic_data.py`).
> - The dataset models realistic statistical correlations across Indian payment methods (UPI, Cards, NetBanking), bank success rates, error codes, and customer value tiers.
> - **Zero Merchant-Proven Claims**: Metrics reported in `model_metadata.json` reflect evaluation against the synthetic hold-out test set ($n=5,250$) with zero data leakage. They do NOT represent real-world merchant production performance.

---

## 3. Deployment & Fail-Closed Behavior
- **Artifact Whitelisting**: The four `.joblib` model artifacts are whitelisted in `.gitignore` (`!backend/ml/artifacts/*.joblib`) to ensure consistent, reproducible deployment without external download dependencies.
- **Production Fail-Closed**: In `ENVIRONMENT=production`, if any required `.joblib` artifact is missing, inference immediately fails closed with `ML model unavailable` (HTTP 503). It never silently falls back to heuristic scoring under the name of XGBoost.
- **Deterministic Fallback (Non-Production Only)**: In development and test environments when models are intentionally omitted, fallback scoring is explicitly labeled as `Scoring Mode: Deterministic Fallback` (`Deterministic Fallback Heuristic`), preventing any false attribution to XGBoost or LightGBM.
